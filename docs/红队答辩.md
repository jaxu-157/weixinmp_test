> 由 `/goal` §5 红队流程产出。戴"苛刻审稿人/导师"帽子自我攻击，逐条：**问 → 诚实答 → 还需补的证据**。

> 最近更新：2026-05-26（Round 3）。引用数据见 `docs/结题报告.md` §7/§8、`GOAL_PROGRESS.md`。

## Q1. 这跟 Trident/VisionDroid 用 MLLM 检测 non-crash bug 有什么本质区别？换个 prompt 它不也能输出维度？

**答**：三点硬区别。
1. **输出形态**：Trident 用 GPT-4V 出**自由文本**判定；我们出**离散 5 类 verdict**（Pass/PerformanceRisk/FunctionalFail/RenderBug/Mixed），
   因此能算混淆矩阵、能训练可学习分诊器、能做模态消融——自由文本做不到这些定量评估。
2. **架构成本**：Trident 无 pre-MLLM 过滤，每个界面都喂大模型。我们是 **rule→Qwen cascade，只在歧义带调用 MLLM**。
   歧义带实验（`ambiguous_evaluation.json`）证实：cascade 用 **1/4 成本+1/4 延迟**达到 qwen-always 同等准确率。
3. **证据来源**：Trident 只看视觉；我们融合**视觉+功能+性能**三模态，模态消融显示去掉任一模态对应类的 F1 直接归 0
   （去 visual → RenderBug F1=0；去 perf → Mixed F1=0；去 func → FunctionalFail F1=0）——证明三模态缺一不可。

**还需补**：与 Trident 在**同一批样本**上的头对头对比（目前是机制差异论证 + 各自数据，非同台对比）。

## Q2. 你的 dimensional 分诊就是把规则法包了个分类器，learned 比 rule 强在哪？有显著性吗？

**答**：有数据，但要诚实分场景。
- 训练集 400 样本：DecisionTree 0.910 / RandomForest 0.870 / **Rule baseline 0.740**（macro-F1 0.906 vs 0.721）。
- 真实 14 截图端到端：Rule 85.7% → **Learned 100%**（修正 2 例规则误诊）。
- VT-Bench 350 样本：**Rule 0.880 / RandomForest 0.903**——此处 learned 优势收窄到 ~2pt。

**诚实**：learned 的优势**不是全场景碾压**——在干净分布的 VT-Bench 上只领先约 2pt；优势主要体现在
真实截图的边界误诊修正上。**还需补**：显著性检验（McNemar / bootstrap CI），目前只报点估计，不能声称"显著优于"。

## Q3. Qwen-VL 直接端到端出 verdict，要你这套 cascade + 融合干嘛？省那点钱/延迟值当一个 contribution 吗？

**答**：这是最该被问的，分两层。
1. **成本层（站得住）**：歧义带实验里 cascade=qwen-always 同准确率（87.5%），但**成本 $0.0022 vs $0.0088、延迟 334ms vs 1214ms**——
   逐界面调 MLLM 在小程序持续回归/矩阵化测试场景里成本与延迟不可接受，cascade 的"自信区免费快判 + 仅 25% 歧义带问 MLLM"是实打实的工程价值。
2. **准确率层（必须诚实降级）**：在当前合成歧义带上，**Qwen 并不严格比规则更准**（rule/cascade/qwen 都 87.5%）。
   Qwen 修正了规则的一个假阳（清晰页误报模糊），但漏了一个边界样本。**所以能 claim 的是"cost-accuracy 等价 + 错误画像不同"，不是"MLLM 更准"。**

**还需补**：更大、更真实（非合成）的歧义样本集，以及人工标注的"可感知模糊"基准，才能给 Qwen vs rule 的错误分布一个可信结论（已进 backlog P1）。

## Q4. 只在 uni-app 编出来的小程序上验证，算"真实小程序"吗？换原生小程序还成立吗？

**答**：目前 2 个验证目标（demo-uniapp、foreign-uniapp/ShopMart）都是 uni-app，**这是真实威胁**。
两者 verdict 准确率完全一致 41.7% 提供了"跨小程序通用"的初步证据，但同属 uni-app 工具链，不能证明跨**框架**通用。

**还需补**（已是 P0）：在一个**原生 WXML** 小程序（如 wxapp-mall）上跑零侵入 driver——若原生也跑通，
才能把 claim 从"跨小程序"升级到"跨框架"。这是当前最该补的工程证据，**需微信开发者工具（人类介入）**。

**Round 4 更新（2026-05-27，重要诚实化）**：staged 了两个真正独立的小程序（tdesign-retail / wxapp-mall）后发现：
旧 foreign-uniapp 其实是 demo 的**再皮肤化副本**（保留我的故障 hook），所以旧"跨小程序"证据偏弱。
更关键：**真正独立的第三方小程序无法零侵入注入故障**（小程序沙箱无 DOM/CSS 注入；本地 mock/静态数据无 wx.request 可拦截）。
所以诚实的 claim 必须再拆一层：
- ✅ 能 claim：零侵入 driver 可**0 行集成 attach 任意小程序 + 遍历真实页跑多通道诊断 + 健康页低假阳**（`run_foreign_matrix.py`）。
- ❌ 不能 claim："在任意小程序上检出注入故障"——故障注入要么靠 instrumented 后端（demo），要么靠 app 走可拦截的 wx.request。
- 验证矩阵：独立 app 上报**假阳率**（healthy 页面误报率），而非故障检出率。

## Q5. 41.7% 的 verdict 准确率，凭什么说工程可用？baseline 是什么？随机猜是多少？

**答**：必须澄清这个 41.7% 是**单通道（learned 单独）**的数字，不是系统终值。
- 5 类均匀随机 = 20%；learned 单通道 41.7% 高于随机但**确实不够**。
- **关键发现正是"单通道不可用"**：learned 在三个场景全部收敛到 41–43% → 证明必须多通道。
  多通道（learned+baseline+webug 融合）在 demo 上到 81.0%、foreign 上 61.9%。
- 工程可用性的论据是**多通道融合 + 零侵入接入成本**（13.85%→driver 路径更低），不是单通道分数。

**还需补**：多通道融合在第 3 个（原生）小程序上的准确率，确认 81%/62% 不是 uni-app 过拟合。

## Q6. vs WeDetector 的 bug-pattern、vs Uber 的 service-level 归因，你的正交性是嘴上说说还是有实证？

**答**：定位有事实支撑（见 §7.1 核实后的论文事实），但正交性目前是**论证级**不是**实验级**。
- WeDetector 静态查 3 类源码 bug 模式；我们运行时多模态分诊。互补的**实证**：他们的异步返回规则被我们**实现为运行时 WeBug-R3 功能通道**并在矩阵里生效（R3 跨小程序 9→13 更稳），这是"互补"的代码级证据。
- Uber 做 service-level（哪个后端），我们做 dimensional-level（哪个失效维度）——**正交性目前只有概念论证**，无同数据对比（Uber 工业数据不可得）。

**还需补**：WeDetector 静态规则与我们运行时通道在同一组真实 bug 上的"互补覆盖"量化（各抓到哪些、重叠多少）。

## 小结：当前能站住 vs 必须降级的 claim

**能站住**：
- Qwen-VL 真接入运行时多模态融合（机制 + 产物）。
- cascade 的 **cost-accuracy 价值**（1/4 成本达 qwen-always 同准确率）。
- 三模态**缺一不可**（消融 F1 归零）。
- 在小程序生态里占据**运行时多模态维度分诊 + 零侵入 driver**的空格（§7.1 四篇核实定位）。

**必须降级/补证据**：
- ❌ "MLLM 比规则更准" → 降级为"cost 等价 + 错误画像不同"。
- ❌ "跨小程序通用" → 降级为"跨 uni-app 通用"，待原生小程序验证才能升级为"跨框架"。
- ⚠️ "learned 显著优于 rule" → 待显著性检验，目前只报点估计。
- ⚠️ 与 Trident / WeDetector / Uber 的对比 → 论证级为主，缺同台实验。
